# Task 003 — Engineering Gate E3: Genesis Atlas 500

## Objective

Implement ADR 004 and the E3 work order without weakening E1 or E2. All
state, coverage, semantic, runtime, and learning figures must be derived
from admitted repository evidence.

## Independently testable plan

### E3.0 — Control plane and exact selection

- Preserve the exact 500-candidate selection as reviewable data.
- Validate uniqueness, HTTPS origins, registrable-domain declarations, family
  quotas, bounded text/list fields, authority vocabulary, and explicit
  candidate state without network access.
- Publish orthogonal catalog, policy, technical, publisher, health,
  adapter-trust, and mapping-trust counters.
- Derive an explicit admission work item and dry-run frontier outcome for all
  500 selected origins, including missing-dossier and missing-catalog states.
- Exercise the actual loopback HTTP control plane across all 500 identities
  under bounded concurrency and restart recovery.
- Reject duplicate, malformed, overlong, unknown-state, and evidence-skipping
  inputs with typed errors.

### E3.1 — Catalog and policy

Control implementation status: policy-artifact validation, exact registry binding,
offline RFC 9309 evaluation, scheduler state, and deterministic dry-run
frontier are implemented candidates. TWIRX and the World Bank E2 origin have
catalog and technical evidence, while their policy reviews remain pending and
uncertain. Both schedulers are disabled. The other 498 catalog reviews, all
500 completed policy decisions, and all public-origin egress
admission remain outstanding. A separate process-boundary proof retrieves only
a literal-loopback fixture and replays its robots decision offline.

- Set `catalog.state: cataloged` only after identity evidence exists.
- Set `policy.review_state: completed` only with dated access, robots, terms, attribution, retention,
  authentication, rate, and risk decisions; unknown is explicit and fails
  closed.
- Implement per-origin scheduler state and dry-run decisions before egress.
- Add RFC 9309 conformance and adversarial cases before any live robots use.

### E3.2 — Profiles and observations

- Record evidence-bound interface declarations, capability candidates, effect
  classes, access/economic metadata, provisional offers, and
  publisher-readiness signals without granting execution authority.
- Keep WebMCP, browser, authenticated, write, action, and payment capabilities
  descriptive only; E3.2 may admit only existing compiled public-read E2
  operations.
- Classify bounded APIs, feeds, sitemaps, structured data, server-rendered
  HTML, and discoverable public endpoints.
- Preserve immutable evidence before extraction.
- Keep archive-derived and current-origin evidence distinct.
- Disable XML external entities and implicit remote JSON-LD context loading.

### E3.3 — Native schemas and adapters

- Generate native modules from reviewed origin evidence.
- Require deterministic adapters, bounded parsers, malformed/adversarial
  fixtures, benchmarks, and offline replay.
- Preserve native terms and lexical values before semantic mapping.

### E3.4 — Semantics and agent surface

- Admit versioned mapping claims only after human review and counterexamples.
- Expose deterministic capability search and structured-query fallback.
- Execute only technically live, policy-permitted, healthy, trusted, read-only operations.
- Bind cross-origin results to each source-native statement and proof bundle.

### E3.5 — Operations and gate evidence

- Operate the bounded daily scheduler under measured resource ceilings.
- Publish reliability, drift, revocation, performance, ecosystem, and learning
  evidence without collapsing them into one vanity metric.
- Reproduce three controlled browser-versus-adapter comparisons.
- Run the complete E1, E2, and E3 suites plus GCC, Clang, ASan, UBSan, fuzz,
  race, static analysis, secret scans, and public-surface checks.

## Admission rule

No state dimension can be inferred from evidence in another dimension. E3 remains
unadmitted until all floors in ADR 004 and the gate work order pass.

## Explicit exclusions

Arbitrary public URLs, browser automation, private/authenticated access, write
or payment actions, automatic canon promotion, model execution authority, and
unreviewed publisher claims are outside this task.
